# 모델링 → LLM 인터페이스 (T0-4, T0-6 확정)

모델링 쪽은 테스트셋 전체를 아래 형식으로 넘기고, LLM 쪽에서 300건을 층화 추출한다.

## 파일

| 파일 | 만드는 쪽 | 내용 |
| --- | --- | --- |
| `results/llm_input_full.csv` | 모델링 | 테스트셋 전체, 한 행 = 한 고객 |
| `results/llm_sample_300.csv` | LLM | 위 파일에서 층화 추출한 300건 |
| `docs/variable_dict.csv` | 공동 | 변수 한국어 사전 |

## `llm_input_full.csv` 컬럼

| 컬럼 | 설명 |
| --- | --- |
| `sample_id` | `SK_ID_CURR` |
| `target` | 실제 부도 여부 (0/1) |
| `pd` | 보정된 부도확률 (0~1), 사용자에게 보여주는 값 |
| `base_value` | SHAP 기준값 (log-odds) |
| `group_gender` | `M` / `F` / `XNA` (모형 입력에는 미사용) |
| `group_age` | `청년` / `중년` / `장년` |
| `group_income` | `하` / `중` / `상` |
| `feat__<변수명>` | 원본 피처값 (전처리 전, 사람이 읽을 수 있는 값) |
| `shap__<변수명>` | 해당 변수의 SHAP 값 (log-odds 기준) |

- 변수명은 Home Credit 원본 컬럼명 그대로 쓴다 (예: `feat__EXT_SOURCE_2`).
- 모형에 들어간 변수는 성별을 빼고 전부 넣는다.
- 범주형 변수를 원-핫 인코딩했다면, 더미들의 SHAP 값을 합쳐 원래 변수 하나로 만든다. SHAP은 가법적이라 합산해도 된다. LLM이 `NAME_EDUCATION_TYPE_Higher education` 같은 더미명을 다루지 않게 하기 위해서다.
- `DAYS_BIRTH`처럼 음수 일수로 된 변수는 원본 그대로 두고, LLM 프롬프트를 만들 때 나이·연차로 변환해 보여준다.

## 집단 정의

| 집단 | 기준 | 구간 |
| --- | --- | --- |
| 성별 | `CODE_GENDER` | `M`, `F` (`XNA`는 추출에서 제외) |
| 연령 | `-DAYS_BIRTH / 365.25` | 청년 35세 미만, 중년 35~54세, 장년 55세 이상 |
| 소득 | `AMT_INCOME_TOTAL` | 학습셋 기준 3분위 (하/중/상), 경계값은 학습셋에서 계산해 고정 |

경계 규칙:

- **성별**: `XNA`(전체 4건)는 `llm_input_full.csv`에 `group_gender = XNA`로 남기고, 300건 추출과 성별 집단 분석에서만 뺀다.
- **연령**: 나이는 소수 그대로 쓰고 내림하지 않는다. 청년 `age < 35`, 중년 `35 ≤ age < 55`, 장년 `age ≥ 55`.
- **소득**: 학습셋에서 `q1 = 1/3 분위수`, `q2 = 2/3 분위수`를 계산해 고정한다. 하 `x ≤ q1`, 중 `q1 < x ≤ q2`, 상 `x > q2` (경계값은 아래 구간에 포함, `pd.cut(..., right=True)`와 동일).
  - 소득은 같은 값이 많아(예: 180,000에 약 2.5만 명) 세 집단 크기가 같지 않다. 전체 데이터 기준 대략 하 103K / 중 112K / 상 92K. 균등 크기를 맞추려고 동점을 임의로 쪼개지 않는다.
  - 계산한 `q1`, `q2` 값은 이 문서 아래 "고정값"에 기록한다.

고정값 (모델링 쪽에서 학습셋으로 계산 후 기입):

| 항목 | 값 |
| --- | --- |
| 소득 `q1` | (미정) |
| 소득 `q2` | (미정) |

## 300건 추출

- 성별 2 × 연령 3 × 소득 3 = 18칸, 정확히 **300건**을 뽑는다.
  - 300 = 18 × 16 + 12 이므로 모든 칸에서 16건씩 뽑고, 18칸 중 12칸을 무작위로 골라 1건씩 더 뽑는다 (12칸 × 17건 + 6칸 × 16건).
  - 테스트셋에서 가장 작은 칸도 약 700건이라 부족한 칸은 생기지 않을 것으로 본다. 만약 생기면 그 칸은 있는 만큼 전부 넣고 300건에 못 미친 상태로 둔다 (다른 칸으로 채우지 않음).
- `random_state=42` 고정 (17건 칸 선택과 칸 내 추출 모두)
- 추출 결과에 `cell_id` 컬럼을 추가해 저장. 형식: `<성별>_<연령>_<소득>` (예: `M_장년_상`)
